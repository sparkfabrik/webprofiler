# Copilot Instructions for Webprofiler Module

This file provides instructions for GitHub Copilot when working with the Webprofiler Drupal module.

## Project Overview

Webprofiler is a Drupal module that extracts, collects, stores, and displays profiling information for Drupal applications. It replaces several Drupal subsystems to collect profiling information and should **never be used in production** due to performance implications.

## Development Environment

This project uses DDEV with the `ddev-drupal-contrib` addon for local development and testing. The environment is automatically set up via the `.github/workflows/copilot-setup-steps.yml` workflow when you start working.

### Key Technologies

- **Drupal**: Version 11+ (PHP 8.3+)
- **DDEV**: Local development environment with Docker
- **Testing**: PHPUnit, Nightwatch (browser tests)
- **Code Quality**: PHP_CodeSniffer, PHPStan

## When Making Changes

### 1. Testing Your Changes

Always test changes before marking work complete:

```bash
# Run relevant tests
ddev phpunit

# For specific tests
ddev phpunit tests/src/Unit/YourTest.php

# Check code style
ddev phpcs

# Run static analysis
ddev phpstan
```

### 2. Code Style and Quality

This project follows Drupal coding standards:

- Use `ddev phpcs` to check for coding standard violations
- Use `ddev phpcbf` to automatically fix coding standard issues
- Run `ddev phpstan` for static analysis before committing

### 3. Manual Testing

For UI or functional changes:

```bash
# Get a one-time login link
ddev drush uli

# Access the site
ddev launch

# Clear caches after changes
ddev drush cr

# Check module configuration
# Visit /admin/config/development/devel/webprofiler
```

### 4. Module-Specific Commands

```bash
# Enable the module
ddev drush en webprofiler -y

# Check module status
ddev drush pml | grep webprofiler

# Export database query data
ddev drush webprofiler:export-database-data <token> /tmp
```

## Working with Tests

### Test Structure

- `tests/src/Unit/`: Unit tests (fast, no Drupal bootstrap)
- `tests/src/Kernel/`: Kernel tests (minimal Drupal bootstrap)
- `tests/src/Functional/`: Functional tests (full Drupal installation)
- `tests/src/FunctionalJavascript/`: Browser tests with JavaScript

### Running Tests

```bash
# All tests
ddev phpunit

# Specific test suite
ddev phpunit --testsuite=unit
ddev phpunit --testsuite=kernel
ddev phpunit --testsuite=functional

# Single test file
ddev phpunit tests/src/Unit/SomeTest.php

# Single test method
ddev phpunit --filter testMethodName
```

## Common Tasks

### Adding a New Feature

1. Create/modify the necessary PHP files in `src/`
2. Write tests in `tests/src/`
3. Run tests: `ddev phpunit`
4. Check code style: `ddev phpcs`
5. Run static analysis: `ddev phpstan`
6. Test manually if UI is involved: `ddev drush uli`

### Fixing a Bug

1. Write a test that reproduces the bug (if possible)
2. Fix the bug
3. Verify the test passes: `ddev phpunit`
4. Run full test suite to ensure no regressions
5. Check code quality: `ddev phpcs && ddev phpstan`

### Updating Dependencies

```bash
# Update composer dependencies
ddev composer update

# Rebuild the site
ddev drush cr
ddev drush updb -y
```

## Important Configuration

### Settings for Time Metrics

To enable time metrics collection, add to `settings.php`:

```php
$settings['tracer_plugin'] = \Drupal\webprofiler\Plugin\Tracer\StopwatchTracer::class;
```

### Disabling Custom Error Handler

If needed, add to `settings.php`:

```php
$settings['webprofiler_error_page_disabled'] = TRUE;
```

## Performance Considerations

Remember that Webprofiler is a development tool:

- It has performance overhead
- It should never be enabled in production
- It instruments Drupal internals for profiling
- Test performance impact when making changes

## Before Completing Work

Always perform these checks:

1. ✅ Run the test suite: `ddev phpunit`
2. ✅ Check coding standards: `ddev phpcs`
3. ✅ Run static analysis: `ddev phpstan`
4. ✅ Clear caches: `ddev drush cr`
5. ✅ Test manually if UI changes were made
6. ✅ Verify no unintended files are being committed

## Troubleshooting

### DDEV Issues

```bash
# Restart DDEV
ddev restart

# Rebuild containers
ddev stop && ddev start

# Check project status
ddev describe
```

### Module Issues

```bash
# Rebuild cache
ddev drush cr

# Reinstall module
ddev drush pmu webprofiler -y
ddev drush en webprofiler -y

# Check for errors
ddev drush wd-show --severity=Error
```

### Test Failures

```bash
# Clear test caches
ddev drush cr

# Ensure database is fresh
ddev drush site:install -y
ddev drush en webprofiler -y

# Run tests with verbose output
ddev phpunit --verbose
```
